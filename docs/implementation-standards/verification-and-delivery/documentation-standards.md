# Documentation Standards

## Rules

- Update Surface Area entries when public capabilities change.
- Update contract documentation when behavior or compatibility changes.
- Record significant design choices as decision records.
- Document non-obvious invariants and operational constraints.
- Comments explain intent, constraints, or tradeoffs. They do not restate code.
- Keep examples compilable or clearly marked as illustrative.
- Use ontology-approved terms and current canonical addresses.
- Add aliases and rename records when names change.
