# System Design

> [!role]
> The Solution Architect owns this process. Its output defines the system decomposition and the constraints passed to Application Architects and the Project Manager.

## Inputs
- Approved requirements owned by the Product Owner.
- Existing System Design.
- Existing component contracts and Surface Area.
- Current ontology and architectural decisions.

## Process
1. requirements-analysis
2. volatility-analysis
3. decomposition
4. structure
5. composition
6. design-validation

## Outputs
- Updated System Design.
- Component boundaries and responsibilities.
- Required component interactions.
- System-level constraints and quality requirements.
- Identified impacted components and Application Architects.
- Information sufficient for the PM to perform Project Design.

> [!constraint]
> The SA defines the system decomposition. Application Architects do not independently redefine it.
